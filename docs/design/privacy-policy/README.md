## Ce que la page montre

Le texte complet de `/confidentialite`, en français et en anglais, prêt à devenir les clés `Privacy.*` : les onze sections de la structure d’organizer-account v4, dans son ordre et avec ses titres. Il décrit ce que fait le produit une fois #581 livrée, d’après `origin/main` et les maquettes approuvées. Les faits qu’on ne peut pas établir depuis le dépôt portent un repère entre crochets dans le texte même ; un test les refuse à la fusion (PP2).

## Le problème

Le champ e-mail de `/nouveau` ne part pas en production sans cette page (décision 28 d’organizer-account) : #614 attend #612, qui attend le texte du propriétaire. La structure dit quoi couvrir ; elle ne dit pas les phrases, et sur deux points elle contredit le code (le cookie de session, la mesure d’audience).

## Critères d’acceptation

Ils complètent OA10.3 et OA10.4, qui restent.

- **PP1** `/confidentialite` répond 200 en FR et en EN (cookie `NEXT_LOCALE`). Un h1, `Privacy.title`, puis exactement onze h2, dans l’ordre de la table, aux textes de leurs clés `.title` ; chaque clé est rendue, dans l’ordre, avec son rôle (Playwright contre `messages/*.json`).
- **PP2** Aucun message `Privacy.*`, FR ou EN, ne contient `[À COMPLÉTER`, `[À VÉRIFIER`, `[À VALIDER`, `[À FIXER`, `[TO COMPLETE`, `[TO CHECK`, `[TO VALIDATE` ni `[TO SET` (Vitest). Le test arrive avec la page.
- **PP3** Dans un contexte neuf, `/confidentialite` ne fait aucune requête vers un autre hôte et ne pose aucun cookie (comme K5).
- **PP4** Dans le contenu, deux liens seulement : « Nous contacter » (`Contact.link`) vers `CRISP_CHAT_URL`, et « cnil.fr » vers `https://www.cnil.fr/fr/plaintes`, chacun `target="_blank"`, `rel="noopener noreferrer"`, `Contact.newTab` en `sr-only`, au moins 44 px. Aucune requête vers Crisp avant un tap.
- **PP5** Captures à 360 px, FR et EN, sans débordement horizontal.
- **PP6** Sans JavaScript, le HTML servi contient `Privacy.updates.body`.
- **PP7** `analyticsBeforeSend` rend `null` pour `/confidentialite`, `/connexion` et `/mes-evenements` (Vitest).
- **PP8** Après le scénario (créer un événement sans session, s’inscrire avec prénom et numéro, replier l’espace organisateur, changer de langue ; puis ouvrir une session dans un autre contexte) : chaque clé de `localStorage` a l’une des formes `fullcar:personal-token:{id}`, `fullcar:session`, `fullcar:admin-token:{id}`, `fullcar:organiser-folded:{id}` ; `sessionStorage` est vide ; le seul cookie est `NEXT_LOCALE` ; aucune valeur ne contient le prénom, le numéro ni l’adresse saisis (Playwright).
- **PP9** `/confidentialite` est dans `publicPaths` : sitemap, URL canonique, indexable.
- **PP10** Fusion par l’humain (OA10.4) ; le champ e-mail de `/nouveau` ne part pas sans cette page (décision 28).

## Décisions

1. Decision : une nouvelle page `privacy-policy`, pas une révision d’organizer-account. — Reason : organizer-account v4 est approuvée et copiée (#582) ; sa section ne donne que la structure ; précédent de `remove-person` et d’`event-description`. Elle remplace la clé de maquette `Privacy.draft`.
2. Decision : les onze titres de section sont ceux de la structure, mot pour mot. — Reason : OA10.4 les teste.
3. Decision : le jeton de session est décrit dans le stockage du navigateur, pas comme un cookie. — Reason : la structure disait « cookie de session » ; l’architecture n’en a pas (décision 3 du coordinateur sur #581).
4. Decision : la mesure d’audience est décrite, dans « Ce que nous ne faisons pas », comme l’exception. — Reason : la structure disait « pas de mesure d’audience », le code en a une (#346). Q4 laisse le choix au propriétaire.
5. Decision : ni « aucun tiers » ni « aucun traceur » au sens large ; « aucun script chargé depuis un autre site ». — Reason : Vercel reçoit chaque requête et calcule une empreinte de visite ; la phrase retenue est vraie et vérifiable.
6. Decision : pas de lien perso. — Reason : #67 n’est pas livré. Ensuite, `Privacy.storage.personal` gagne : « Le lien perso et son QR code le contiennent : quiconque les a peut modifier vos inscriptions. » / “The personal link and its QR code contain it: anyone who has them can change your sign-ups.”
7. Decision : un fait non vérifié porte son repère dans la chaîne même, FR et EN, et PP2 le refuse. — Reason : une note à côté se perd ; dans la chaîne, la page ne peut pas partir avec.
8. Decision : aucune durée de prestataire sans source ; celles qui sont citées le sont « selon » lui. — Reason : ne rien inventer ; elles changent sans nous.
9. Decision : l’exemple du jour 30 (retour le 12 décembre, effacé le 11 janvier). — Reason : « le 30e jour après » se lit de deux façons ; l’exemple n’en laisse qu’une, celle de `dayThirty`.
10. Decision : en français, jamais « trajet » seul : « l’aller », « le retour », « le sens ». — Reason : le glossaire le déconseille (confusion avec Ride). L’anglais garde “trip”, comme l’interface.
11. Decision : hors de l’application, le participant se fait reconnaître, dans la discussion Crisp, par le lien de l’événement et son prénom. — Reason : il n’a pas de compte.
12. Decision : les liens sont des clés de texte, l’adresse dans le code ; pas de texte riche. — Reason : aucun message n’utilise `t.rich` ; une adresse dans une traduction changerait sans revue.
13. Decision : « Nous répondons dans un délai d’un mois au plus. » — Reason : le délai de l’article 12 du RGPD ; à retirer si le propriétaire ne veut pas s’y engager.
14. Decision : l’aperçu d’une messagerie est mentionné. — Reason : risque accepté sur #654 ; une personne nommée dans une description doit le savoir.
15. Decision (v4) : les e-mails disent que Brevo peut compter ouvertures et clics de façon anonymisée, sans les rattacher au destinataire, avec le repère `[À VÉRIFIER : pixel et liens réécrits dans un email réel]` ; ni « aucun pixel » ni « aucun lien réécrit ». — Reason : le suivi est « Suivi anonymisé » (correction du propriétaire), et personne n’a encore regardé un vrai e-mail.
16. Decision (v2) : la garantie de transfert est dite à la ligne de chaque prestataire. — Reason : elle diffère (clauses types, DPF, ou les deux).
17. Decision (v3) : Crisp est le seul moyen de contact, droits compris, et sa ligne le dit ; le texte dit qu’il n’y a pas d’adresse e-mail. — Reason : réponse du propriétaire à Q2. La base reste 6.1.f (Q3).
18. Decision (v3) : pour Neon et Sentry, la garantie de transfert ne couvre que l’accès depuis l’extérieur de l’Union, par la société ou ses sous-traitants. — Reason : leurs données sont à Francfort ; en dire plus affirmerait un transfert qui n’a pas lieu.
