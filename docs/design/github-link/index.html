Lien « Code source sur GitHub »

Version 1.2 (v1.1 approuvée, retouches de mots ; epic #489). Le bas de page partagé (src/components/contact/contact-footer.tsx) gagne un lien vers le dépôt public https://github.com/olaurendeau/fullcar, sur toutes les pages qui ont ce bas de page. Pour qu’il tienne à 360 px, le bas de page passe d’une ligne à deux, toujours les mêmes : ce qui reste dans l’application en haut, ce qui en sort en bas. « Nous contacter » reste le dernier lien de la page. Maquettes à la taille réelle, 360 px de large ; le cadre pointillé bleu marque le bas de page qui change, le fond bleu pâle le lien nouveau (repère de maquette seulement).

Deux lignes centrées, dans cet ordre de lecture, de tabulation et d’affichage. Ligne 1 : « Accueil » (absent de /), puis le bouton de langue. Le lien nouveau a exactement l’allure de « Nous contacter » : 14 px, gris muted-foreground, souligné, 44 px de haut, l’anneau de base au clavier. Pas d’icône.

Pourquoi deux lignes fixes

À 360 px, la colonne laisse 328 px. « Accueil », « English », un lien GitHub et « Nous contacter » n’y tiennent pas sur une ligne en français, quel que soit le libellé, même « GitHub » seul. Laisser la ligne se replier d’elle-même donne un résultat qui dépend de la police du téléphone (Roboto, San Francisco, Segoe) et de la langue : la capture du test ne montrerait pas ce que voit le téléphone. Deux lignes fixes donnent le même bas de page partout.

Décisions

  1. Décision : le lien est dans ContactFooter, donc sur toutes les pages qui ont le bas de page, / comprise ; pas dans le panneau organisateur. — Raison : un bas de page identique partout (décision 7 de #232) ; une page future qui prend le bas de page prend le lien.
  2. Décision : « Code source sur GitHub », pas « GitHub » seul. — Raison : un parent qui organise un covoiturage ne sait pas ce qu’est GitHub ; le libellé dit ce qu’il trouvera derrière.
  3. Décision : du texte, sans logo. — Raison : comme « Accueil » et « Nous contacter » ; lucide-react 1.55 n’a plus d’icône de marque, et un logo dessiné à la main est du code à tenir pour un lien discret.
  4. Décision : deux lignes fixes, à toutes les largeurs : « Accueil », langue ; puis « Code source sur GitHub », « Nous contacter ». — Raison : quatre éléments ne tiennent pas sur 328 px en français ; un repli laissé au navigateur dépend de la police et de la langue. La ligne 1 reste dans l’application, la ligne 2 en sort, en nouvel onglet toutes les deux.
  5. Décision : « Nous contacter » reste le dernier lien de la page. — Raison : K1 à K7 de #69 tiennent sans retouche, ainsi que C11.4 (« Nous contacter » défile au-dessus de la barre de messages).
  6. Décision : target="_blank", rel="noopener noreferrer", adresse fixe. — Raison : comme « Nous contacter » (K2, K4) ; l’espace organisateur porte le jeton dans le fragment, et l’identifiant de l’événement dans le chemin.
  7. Décision : aucune requête vers GitHub avant le tap (ni badge, ni nombre d’étoiles, ni préchargement). — Raison : aucun tiers sur les pages (K5 de #69).
  8. Décision : clé Contact.sourceCode, pas de nouvel espace. — Raison : Contact porte déjà tous les mots du bas de page ; la mention de nouvel onglet est réutilisée telle quelle.

Pour le développement

  • src/components/i18n/language-switch.tsx change aussi : il met aujourd’hui before (« Accueil »), le bouton et children (« Nous contacter ») dans une seule rangée flex, le message d’échec au-dessus. Les deux lignes demandent que sa rangée ne porte plus que « Accueil » et le bouton, le message restant au-dessus d’elle, et que la ligne 2 vienne après. La forme du code (prop, composant) est au choix du développeur.
  • Marge à 360 px : la ligne 2 en français mesure environ 321 px sur 328 si l’image Playwright rend system-ui en DejaVu Sans (estimation d’après les métriques de la police, pas une mesure), soit environ 7 px de reste. Un libellé plus long sur cette ligne, dans l’une ou l’autre langue, se revérifie avec G5.

Hors périmètre

  • Un logo GitHub, un badge, le nombre d’étoiles, ou tout appel à GitHub depuis l’application.
  • Un lien « Signaler un problème » vers les issues : le contact reste Crisp.
  • Une licence pour le dépôt, un numéro de version ou de commit dans le bas de page, une page « À propos ».
  • Un en-tête, un lien dans le panneau organisateur, un changement de « Nous contacter ».
  • Un bas de page sur une seule ligne aux grandes largeurs.
